# Ошибки ZenMoney API

!!! warning "Черновик"
    Описывает поведение до живой приёмки записи в ZenMoney; детали могут измениться.

## Как идёт запись

Бот работает через diff API ZenMoney: таймаут 5 с на соединение и 30 с на ответ, не чаще одного запроса в 0,5 с. Чтение при ошибке повторяется до 2 раз; **запись не повторяется никогда**. После «Подтвердить»:

1. Бот читает ZenMoney целиком и пересчитывает план. Если план изменился, ничего не пишется.
2. Операции отправляются порциями по `ZENBOT_WRITE_CHUNK_SIZE` (18). Перед каждой следующей порцией бот проверяет, что изменилось в ZenMoney. Если появилась или изменилась похожая запись (например, синхронизировался банковский плагин или вы что-то внесли в приложении), бот **останавливается**: оставшиеся порции не отправляются, импорт получает статус `partial`. Так бот не создаст дубль того, что пришло из другого источника.
3. После всех порций бот читает ZenMoney и проверяет, что всё отправленное на месте. Если чего-то нет, ждёт 3 с и перечитывает, всего до 3 чтений. Чтения входят в локальный лимит (30 полных чтений за 60 с); в худшем случае проверка длится около 3,5 минут. Только то, чего нет и после этого, считается `VERIFY_FAILED`.

## Проверка токена и сети {#check-token}

HTTP-код ошибки бот не показывает и не сохраняет. Чтобы узнать его, выполните проверку чтения тем же токеном:

```bash
set -a; . ./.env.test; set +a
uv run --frozen python -c 'from zenbot.config import ClientSettings; from zenbot.zenmoney_client.transport import ReadOnlyTransport, TransportError
c = ClientSettings.from_env()
try:
    d = ReadOnlyTransport(c.zenmoney_token).diff_read(0, retries=0)
    print("OK: transactions =", len(d.get("transaction", [])))
except TransportError as e:
    print("ERROR:", e)'
```

`OK: ...` — токен и сеть работают. Иначе будет, например, `ERROR: read failed after retries: ZenMoney HTTP 401`.

Коды — как [при старте](../configuration/env.md#startup-errors). | Ничего не записано. Исправьте аккаунт, токен или конфиг, перезапустите бота и загрузите выписку заново. |
| То же; проверка: `network error: ConnectionError/Timeout` | Нет сети или ZenMoney недоступен. | Подождать и повторить. |
| То же; проверка: `HTTP 5xx` | Сбой на стороне ZenMoney. | Подождать, повторить. |

| Бот: `Запись не выполнена, ничего не отправлено (код ...).` | Запись отклонена до отправки; причина — в логе бота (`apply refused [...]`). | Ничего не записано. Причину из лога передайте разработчику. |
| Бот: `Отправлено: X из N, проверено: Y ... Ошибок: E. Сверьте через /export_ids K`, в `/history` статус `partial` | Запись остановлена между порциями (ZenMoney изменился во время записи) или порция не отправилась. | Дождитесь окончания синхронизации плагина и загрузите **тот же PDF** ещё раз: записанное попадёт в «Дубли», остальное будет предложено заново. См. ниже. |
| То же, статус `verify_failed` | Отправлено, но часть операций не видна даже после трёх чтений. | См. ниже. |
| Бот: `Ошибка при записи (код ...). Результат неизвестен` или `Запись не выполнена. Проверьте /status и /history.` | Сбой во время записи. | См. ниже. |

## Результат записи неизвестен {#unknown-result}

Относится к таймауту, статусам `partial`, `started`, `verify_failed` и случаю, когда `проверено` меньше `Отправлено`. Таймаут **не означает**, что ZenMoney ничего не записал: сервер может довести операцию до конца, даже если клиент не дождался ответа.

1. Ничего не удаляйте вручную сразу и не удаляйте аудит-лог.
2. Через 1–2 минуты выполните проверку из [ручного отката](../usage/rollback.md#rollback) (шаг 3): какие операции импорта `LIVE`, а какие `absent`.
3. Чтобы дописать недостающее, загрузите **тот же PDF** ещё раз. Id операций постоянные, поэтому уже записанное попадёт в «Дубли», а создано будет только отсутствующее.

Шаг 2 обязателен: бот повторно отправляет те операции, которых не видит при чтении, и если операция на сервере уже есть, но ещё не видна, она уйдёт ещё раз.

HTTP 400 на запись стабильной расшифровки не имеет. Не повторяйте запись вслепую, передайте разработчику время и номер импорта.
