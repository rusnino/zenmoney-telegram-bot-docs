# Установка и первый запуск

!!! warning "Черновик"
    Описывает поведение до живой приёмки записи в ZenMoney; детали могут измениться.

## Требования

Python 3.11 или новее и [uv](https://docs.astral.sh/uv/). Проверено с `uv 0.13.0`; `uv.lock` фиксирует `python-telegram-bot 22.8`, `pdfplumber 0.11.10`, `pydantic 2.14.2`, `requests 2.34.2`. Команды ниже — для терминала Linux/macOS (bash/zsh), из корня репозитория.

## Установка

!!! note "Репозиторий приватный, нужен доступ"
    `git clone` сработает только у тех, кому выдан доступ к репозиторию.

```bash
git clone https://github.com/rusnino/zenmoney-telegram-bot.git
cd zenmoney-telegram-bot
uv sync --frozen --extra dev
uv run --frozen --extra dev pytest -q
```

Ожидаемо: `... passed` без `failed`.

## Два режима: test и prod

Режим задаёт обязательная переменная `ZENBOT_ENV`:

- **`test`** — отдельный тестовый аккаунт ZenMoney (счета названы с префиксом `TEST `), **отдельный тестовый бот в Telegram**, свой конфиг, свой каталог данных;
- **`prod`** — ваш настоящий аккаунт ZenMoney и боевой бот.

**Начинайте с тестового аккаунта.** Автоматического отката нет ([Аудит-лог и ручной откат](usage/rollback.md)), а ошибка на боевом аккаунте означает ручную чистку реальных данных.

## Файлы тестового режима

```bash
umask 077
cp .env.example .env.test
cp config.bot.test.example.toml config.bot.test.toml
mkdir -p ../zenbot-test-data
chmod 600 .env.test config.bot.test.toml
chmod 700 ../zenbot-test-data
realpath ../zenbot-test-data config.bot.test.toml
```

`realpath` печатает абсолютные пути для `ZENBOT_DATA_DIR_TEST` и `ZENBOT_CONFIG`. Боевой набор — так же, но из `config.example.toml`: `.env.prod`, `config.prod.toml`, каталог `../zenbot-data` (`ZENBOT_DATA_DIR`). Создавайте его после проверки на тестовом аккаунте.

- Если каталога данных нет, бот создаст его с правами `700`. Уже существующий каталог бот не трогает: если он доступен группе или другим, в логе будет `ZENBOT_DATA_DIR is accessible to group/others; restrict it to the owner (chmod 700)` — выполните `chmod 700 <каталог>`. Файлы внутри бот создаёт с правами `600`.
- При первом запуске бот кладёт в каталог данных метку `.zenbot-mode` (`prod` или `test`). После этого каталог принимает только свой режим. Метку не удаляйте и не правьте.
- Файлы `.env.*`, `config*.toml` (кроме примеров) и `*.sqlite3` уже в `.gitignore`. Реальные PDF-выписки в репозитории не храните.

Заполните `.env.test` и конфиг: [Переменные окружения](configuration/env.md), [Конфиг счетов](configuration/accounts.md).

## Запуск

```bash
set -a; . ./.env.test; set +a
uv run --frozen python -m zenbot.bot.app
```

Бот работает, пока открыт терминал, и пишет лог в него же. Остановка — `Ctrl+C`. При старте бот проверяет режим и читает аккаунт ZenMoney; при отказе он не запустится и напишет причину ([ошибки запуска](configuration/env.md#startup-errors)). В логе старта — строка `starting: ZENBOT_ENV=test, write_enabled=False`.

Напишите **своему боту этого режима** `/status`. Ожидаемо в тестовом режиме:

```text
Режим: ТЕСТОВЫЙ аккаунт
Запись: DRY-RUN (запись выключена)
```

В боевом первая строка — `Режим: боевой`. Эта же строка — первая в каждом preview: прежде чем подтверждать, смотрите, в каком вы режиме.

Перезапуск стирает из памяти всё неподтверждённое: preview, `/manual`, `/present` и решения `/transfers`. Уже записанные операции и аудит-лог не затрагиваются.

## Dry-run (по умолчанию)

При `ZENBOT_WRITE_ENABLED=false` работает всё: загрузка, разбор, чтение ZenMoney, preview и списки. Кнопка «Подтвердить (N)» тоже работает, но вместо записи бот отвечает `DRY-RUN: ничего не отправлено в ZenMoney. Было бы создано операций: N.` В аудит-лог dry-run не пишется, поэтому `/history` его не покажет.

## Как включить запись

1. Остановите бота.
2. В `.env` этого режима поменяйте одну строку: `ZENBOT_WRITE_ENABLED=true`.
3. Запустите бота заново. Без перезапуска настройка не применяется.

Режим `test` сам по себе не означает dry-run: с `ZENBOT_WRITE_ENABLED=true` тестовый бот пишет в тестовый аккаунт.

Перед первым подтверждением проверьте:

1. Вы пишете нужному боту: `/status` начинается с `Режим: ТЕСТОВЫЙ аккаунт` или `Режим: боевой`.
2. `/status` показывает `Запись: ЗАПИСЬ ВКЛЮЧЕНА` и нет строки `Счетов из конфига нет в ZenMoney`, а preview — `Режим: ЗАПИСЬ ВКЛЮЧЕНА — подтверждение отправит операции в ZenMoney.`
3. Каждый `zenmoney_account_id` в TOML — счёт этого же аккаунта ZenMoney в нужной валюте ([как проверить](configuration/accounts.md#zenmoney-ids)).
4. Прочитаны preview, весь список `/manual`, `/present` и `/transfers`.
5. Число «К созданию» совпадает с ожиданием; «Уже есть» и «Дубли» объяснимы.
6. Исходный PDF сохранён у вас.

Вернуть dry-run: `ZENBOT_WRITE_ENABLED=false` и перезапуск.

## Порядок перехода к боевому аккаунту

1. **Тестовый аккаунт ZenMoney и тестовый бот** с записью: загрузка выписок, подтверждение, повторная загрузка тех же выписок (должны быть только «Дубли»), переводы, `/uncategorized`, `/unreadable`, `/reset_balance`.
2. **Боевой аккаунт в dry-run**: `.env.prod`, `ZENBOT_WRITE_ENABLED=false`. Загрузите реальные выписки и сверьте preview: «К созданию», «Уже есть», «Вручную», блокировки, переводы.
3. **Включение записи на боевом**: `ZENBOT_WRITE_ENABLED=true` в `.env.prod`, перезапуск, первый импорт — одна небольшая выписка.

Одна и та же выписка может загружаться и в тестовый, и в боевой аккаунт: id операций в разных аккаунтах разные, каталоги данных и аудит-логи режимов раздельные.
