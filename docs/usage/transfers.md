# Переводы между своими счетами

!!! warning "Черновик"
    Описывает поведение до живой приёмки записи в ZenMoney; детали могут измениться.

Перевод с одного своего счёта на другой (например, Forte → Kaspi) виден в двух выписках: расход в одной, приход в другой. Без объединения в ZenMoney появились бы две несвязанные операции. Бот **предлагает** объединить их в одну операцию-перевод, но делает это только по вашей кнопке.

## Когда бот предлагает перевод

В пакете есть расход на одном своём счёте и приход на другом, и:

- валюта одна;
- даты отличаются не больше чем на `date_window_days` (по умолчанию 2 дня);
- разница сумм не больше комиссии: `fee_abs` или `fee_pct` процентов от расхода (берётся большая граница; по умолчанию 0 и 0,5 %);
- с каждой стороны ровно один подходящий кандидат.

Параметры — секция `[transfers]` [конфига](../configuration/accounts.md). Для Kaspi кандидатом в перевод считается пополнение, в «Деталях» которого есть подстрока из `internal_candidate_markers` (по умолчанию «с карты другого банка»).

## Окно решений {#window}

Все кандидаты одного импорта решаются в **одном** сообщении-окне. Оно приходит после preview и списка «Обработать вручную». Бот ничего не сливает сам: каждая пара объединяется только по вашей кнопке, а запись в ZenMoney идёт только после «Подтвердить» в новом preview.

Сверху окна — счётчик `Переводы: осталось решить N операций`. N — операции, а не карточки: он только убывает. Число карточек может вырасти, когда выбор пары разбивает группу (см. ниже).

Если кандидат один, окно сразу показывает его карточку. Если несколько — окно открывается в режиме «Весь список».

### Карточка пары

Пример (синтетические данные):

```text
Переводы: осталось решить 2 операции

Перевод между своими счетами?
Списание (forte …0001):     18.09.26  -50 000.00 KZT  Перевод на свою карту
Поступление (kaspi …0001):  18.09.26  +50 000.00 KZT  Пополнение с карты другого банка
Комиссия/расхождение: 0 KZT.
«Слить» — ОДНА операция-перевод вместо двух. Существующие записи ZenMoney не меняются.
```

| Кнопка | Что будет |
|---|---|
| `Слить` | Одна операция-перевод вместо двух. Получателя у неё не будет: у переводов между обычными счетами ZenMoney его очищает. |
| `Не сливать` | Две обычные операции. |
| `Отложить` | Обе стороны не создаются и уходят во «вручную» (`transfer_wait`). Загрузите выписку второго счёта позже. |
| `« назад` / `далее »` | Листают карточки по кругу. Ничего не решают и план не меняют. |
| `Весь список (N)` | Переход в список (ниже). |
| `Отменить импорт` | Отменяет весь импорт, ничего не записано. |

После решения окно **правится на месте** и показывает следующую нерешённую карточку, сверху строка `✓ Предыдущая: 18.09 -50 000 KZT forte → 18.09 +50 000 KZT kaspi — слить.` Новых сообщений не приходит.

Если пролистать на уже решённую карточку, кнопок решения у неё нет, есть строка `Решение: …` и подсказка «Изменить решение — только «Отменить импорт» и прислать файлы заново».

**Карточка «второй стороны нет»** (`Кандидат в перевод, второй стороны нет`) — одна операция, похожая на половину перевода, без пары в пакете. Кнопки: `Не сливать` (создать как есть) и `Отложить`.

### Карточка выбора пары

Если подходят несколько пар (например, два одинаковых снятия с депозита и одно пополнение карты в тот же день), приходит карточка `Перевод между своими счетами — выберите пару`: одна операция и 2–5 подходящих к ней операций с датой, счётом и суммой. Сам бот пару не выбирает.

- `№1` … `№n` — создать перевод из этой пары. Остальные операции группы сопоставляются заново и появляются следующими карточками: оставшаяся без пары — карточкой «второй стороны нет», ставшая однозначной пара — обычной карточкой. Поэтому карточек может стать больше, а счётчик операций всё равно убывает.
- `Не перевод` — эта операция создаётся как есть.
- `Отложить` — как обычно.

Если в группе нет ни одной операции, к которой подходят от 2 до 5 других, или с группой совпадает ещё и запись, уже существующая в ZenMoney, все операции группы уходят во «вручную» (`transfer_ambiguous`), карточки нет.

### Весь список и пакетные кнопки

`Весь список` показывает все карточки по 12 строк на страницу, у каждой — текущее решение или `без решения`:

```text
Кандидаты в переводы: 3 · осталось решить: 5
1. 18.09 -50 000 KZT forte → 18.09 +50 000 KZT kaspi — без решения
2. 20.09 -20 000 KZT forte → 20.09 +20 000 KZT halyk — без решения
3. 21.09 -7 000 KZT kaspi (одна сторона) — без решения
```

Пакетные кнопки есть **только** в этом режиме, рядом со списком, который они решают:

- `Все пары → слить (N)` — только однозначные пары. Карточки выбора пары и «второй стороны нет» не трогает;
- `Все → не сливать`, `Все → отложить` — все нерешённые карточки, включая группы выбора пары целиком.

После пакетной кнопки окно остаётся списком с итогом `✓ Пакетно: …`; оставшееся решается по одной. `« назад` / `далее »` листают страницы списка (без перехода по кругу), `По одной »` открывает первую нерешённую карточку.

### Итоговая сводка и подтверждение

После последнего решения окно превращается в **итоговую сводку решений** — всегда одно сообщение:

```text
Итог решений по переводам: 3 — слить 2 · не сливать 0 · отложить 1.
Записи ещё нет: подтвердите новый preview ниже.
1. 18.09 -50 000 KZT forte → 18.09 +50 000 KZT kaspi — слить
2. 20.09 -20 000 KZT forte → 20.09 +20 000 KZT halyk — слить
3. 21.09 -7 000 KZT kaspi (одна сторона) — отложить
```

Длинная сводка листается `далее »` правкой того же сообщения. Кнопок решения в ней нет, она больше не меняется. Сразу под ней приходит **новый preview** с кнопкой `Подтвердить (N)` (если нет других [блокировок](../faq/blocks.md)). В ZenMoney ничего не записано, пока вы её не нажали.

## Правила окна

- **Пока хоть одна операция без решения, записать нельзя.** Preview пишет `Переводы: осталось решить N операций — окно решений ниже. … Окно заново: /transfers` и предлагает только `Отменить импорт`.
- **Окно одно.** `/transfers` присылает его заново внизу чата; старое окно меняется на «Окно решений по переводам перенесено ниже.» и теряет кнопки. Нажатие на кнопку устаревшего окна отклоняется сообщением «Это окно устарело — актуальное ниже (или /transfers)».
- **Решение не меняется.** Повторное нажатие по уже решённой карточке отклоняется всплывающим сообщением «Решение по этой карточке уже принято: … Изменить его — «Отменить импорт» и прислать файлы заново.»; окно не правится. Если карточка за это время изменилась — «Карточка устарела или решение недоступно — ничего не изменено (/transfers).»
- **Отмена из окна.** `Отменить импорт` снимает кнопки с окна и preview; к preview дописывается статус «✖️ Импорт отменён…».
- Если вторая сторона уже есть в ZenMoney, бот ничего не создаёт и пишет во «вручную»: «объедините в приложении ZenMoney».
- Решения хранятся только в памяти до подтверждения импорта ([подробнее](import.md#memory-only)).

## Что остаётся в истории чата

| Сообщение | Что в нём видно |
|---|---|
| Первый preview | Счётчик «осталось решить», кнопки «Подтвердить» нет. Когда приходит новый preview, к старому дописывается «(устарел — см. ниже)» и кнопки снимаются. |
| Окно решений | После последнего решения это же сообщение — **итоговая сводка**: каждая пара или сторона и выбранное решение. |
| Старые окна (после `/transfers`) | «Окно решений по переводам перенесено ниже.», без кнопок. |
| Новый preview | После подтверждения дополняется строкой «✅ Подтверждено — итог ниже» (или «⚠️ Запись не выполнена…»), итог записи с номером импорта — отдельным сообщением ниже. |

**Где искать решение по конкретной паре:** в итоговой сводке, найдите строку по дате и сумме. Первая страница сводки остаётся в чате всегда; остальные страницы листаются, пока импорт не подтверждён или не отменён. После записи слитая пара — одна строка в `/export_ids <номер импорта>` (счёт — счёт списания), а в [аудит-логе](rollback.md) исходные операции пары — в таблице `absorbed_tx`.
