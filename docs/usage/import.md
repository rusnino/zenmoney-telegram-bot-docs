# Импорт выписки

!!! warning "Черновик"
    Описывает поведение до живой приёмки записи в ZenMoney; детали могут измениться.

## Шаги

1. Пришлите PDF в личный чат с ботом (файл, а не фото). Ограничения: до 10 МиБ на файл, до 10 файлов и 40 МиБ в одном пакете, не больше 10 файлов за 5 минут. Все файлы, присланные подряд, собираются в **один** импорт.
2. Разбор начинается через ~4 с после последнего файла или по кнопке `Разобрать N файл(ов)`. Окно сбора закрывается не позже чем через 3 минуты после первого файла. `Отменить пакет` удаляет файлы, ничего не разбирая.
3. Файлы разбираются по очереди. Большой файл может разбираться до 5 минут: бот предупредит об этом отдельным сообщением.
4. Придёт preview, затем список «Обработать вручную» и карточки переводов (если есть).
5. Прочитайте всё, решите [переводы](transfers.md), при необходимости примите риск ([Блокировки](../faq/blocks.md)).
6. Нажмите `Подтвердить (N)`. При включённой записи бот отправляет операции порциями по 18 и после всех порций перечитывает ZenMoney. Обычно это секунды; если лимит чтений исчерпан, проверка может занять **до ~3,5 минут** — не перезапускайте бота в это время. Затем бот ответит `Отправлено: X из N, проверено: Y. Импорт №K.` **Запишите номер K**: по нему ищутся операции для [отката](rollback.md). Если `X` меньше `N` — [Результат записи неизвестен](../faq/api-errors.md#unknown-result).

Пока есть неподтверждённый импорт, новые файлы не принимаются: ответ `Есть неподтверждённый импорт: подтвердите или отмените его.` Неподтверждённый импорт живёт 15 минут.

## Поля preview

Первая строка preview — режим: `Режим: ТЕСТОВЫЙ аккаунт` или `Режим: боевой`.

| Поле | Что значит |
|---|---|
| `К созданию` | Новые операции, которые уйдут в ZenMoney после подтверждения. |
| `Уже есть в ZenMoney ... (пропущены)` | Операции, найденные в ZenMoney из другого источника (плагин банка, ручной ввод). Обычно бывает только на счетах с `mode = "cross_source"`; ещё сюда попадают стороны перевода, который уже есть в ZenMoney. Список — `/present`. |
| `Вручную` | Сомнительные операции: бот их **не создаёт**, но остальное записать можно. Список приходит сразу после preview, повторно — `/manual`. |
| `Дубли (свои, ранее загруженные)` | Операции, которые бот уже создавал раньше. Повторная загрузка той же или пересекающейся выписки их пропускает. |
| `блокировок` | Причины, из-за которых записать нельзя вообще ничего; коды — в строке `Запись невозможна:` ([Блокировки](../faq/blocks.md)). |
| `Режим сопоставления` | `строгий`: похожая запись → «вручную», ничего не пропускается молча. `между источниками`: совпавшие записи пропускаются как «уже есть». |
| `Счета выписки` | Есть только у многосчётных выписок (Halyk): счета по последним 4 символам. |
| `Файлы пакета` | Только для пакета: состояние каждого файла (`ок` / `ЗАБЛОКИРОВАН: коды` / `ИСКЛЮЧЁН`). |

В конце preview бывают пояснения: исключённые hold-операции, «Остатки в шапке выписки не используются как истина», нестыковка остатков с соседней выпиской, нераспознанные записи ZenMoney, кандидаты в переводы.

**Если счёта из конфига нет в ZenMoney.** Под строкой режима будет `Счетов из конфига нет в ZenMoney: N — пакет с операциями по таким счетам не будет записан`. Если в выписке есть хоть одна операция по такому счёту, **не записывается весь пакет** (блокировка `account_absent`). Сверьте `account_map` со [списком счетов](../configuration/accounts.md#zenmoney-ids), исправьте и перезапустите бота.

## Причины в списке «Обработать вручную»

Каждая строка — операция из выписки, которую бот **не создаст**, и причина; в скобках — код из аудит-лога.

| Текст в списке (код) | Что делать |
|---|---|
| «похожа на существующую запись (счёт, сумма, ±1 день)» (`similar_existing`, `lookalike`) | Найдите в ZenMoney указанную запись (её id и данные — в той же строке). Если это та же операция — ничего не делать; если другая — внесите вручную. |
| «возможно та же операция — совпали дата и MCC» (`possible_same_date_mcc`), «есть запись с той же суммой и датой, описание не подтверждает» (`weak_match`) | То же. |
| «несколько похожих записей, однозначного соответствия нет» (`ambiguous_match`) | Сверьте вручную. |
| «запись с таким id уже есть, но содержимое отличается» (`id_content_mismatch`) | Запись бота в ZenMoney кто-то изменил или она не распознана. Ничего не делать либо поправить вручную. |
| «бот уже записывал эту операцию, но в ZenMoney её нет — возможно, она удалена» (`deleted_in_zenmoney`) | Вы удалили эту операцию в ZenMoney. Бот её больше не создаст. Если она нужна — внесите вручную. |
| «одинаковые операции сопоставились по-разному» (`split_group`) | В выписке несколько одинаковых операций, и бот не смог сопоставить их единообразно: вся группа не создаётся. Посчитайте такие операции в PDF и в ZenMoney и добавьте недостающие вручную. |
| «в выписке только часть одинаковых операций» (`partial_group`), «слишком большая группа одинаковых операций» (`group_limit`) | То же: сверьте количество вручную. |
| «потолок поиска пар превышен, автопоиска пар не было» (`transfer_search_truncated`) | Слишком много возможных пар переводов. Операция может быть половиной перевода: внесите вручную или загрузите меньший период. |
| «несколько возможных пар для перевода» (`transfer_ambiguous`) | Разберите вручную. |
| «вероятный перевод: вторая сторона уже есть в ZenMoney» (`transfer_existing_side`) | Объедините в приложении ZenMoney или внесите вторую сторону вручную. |
| «вы выбрали «подождать»» (`transfer_wait`) | Загрузите выписку второго счёта. |
| «парная сторона не загружена» (`partner_not_loaded`) | Из пакета исключён файл: загрузите пакет заново целиком или внесите вручную. |
| «совпала запись-«ожидание» (hold)» (`hold_pending`) | Дождитесь проведения операции в банке и загрузите следующую выписку. |
| «операция не классифицирована или не сопоставлена» (`needs_review`) | Внесите вручную. |
| «покупка слита с курсовой разницей ..., а в ZenMoney уже есть запись с её исходной суммой» (`fx_original_amount`) | Проверьте, не та же ли это покупка ([Kaspi](../banks.md#kaspi)). |
| `заблокировано (<код>): ...` | Это блокировка, а не операция: [Блокировки](../faq/blocks.md). |
| `предупреждение парсера (<код>): ...` | [Ошибки разбора PDF](../faq/pdf-errors.md#warnings). |
| «проверить категорию (создаётся как есть)», «сумма покупки уменьшена на курсовую разницу» | Справка: эти операции **будут** созданы. |

## `/manual`, `/present`, `/transfers` хранятся только в памяти

Эти списки и решения по переводам живут **только в памяти процесса и только для текущего неподтверждённого импорта**. Они исчезают, если:

- нажато «Подтвердить» (в том числе в dry-run) или «Отменить»;
- прошло 15 минут без подтверждения;
- бот перезапущен или упал.

Поэтому **просматривайте `/present` и `/manual` до подтверждения**. Если списки пропали, загрузите те же PDF заново: уже созданные операции попадут в «Дубли». Кнопки «далее» в длинных списках работают 30 минут; если пишет `Список устарел`, повторите команду.
