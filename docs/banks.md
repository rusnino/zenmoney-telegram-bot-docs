# Банки и выписки

!!! warning "Черновик"
    Описывает поведение до живой приёмки записи в ZenMoney; детали могут измениться.

Поддерживаются PDF-выписки **Forte**, **Kaspi** и **Halyk**. Нужен оригинальный PDF из приложения или интернет-банка: не скан, не фото, не «печать в PDF», до 10 МиБ и до 200 страниц.

Банк определяется по структуре файла, а не по названию в тексте. Если бот не определил банк, укажите его командой `/bank forte|kaspi|halyk` и пришлите файл снова первым файлом нового пакета. Другие банки без доработки кода не поддерживаются: файл будет отклонён.

Остатки из шапки выписки бот никогда не отправляет в ZenMoney: они используются только для сверки строк.

## Forte {#forte}

Карты, вклад, валютный счёт — каждый счёт отдельным файлом и отдельной записью `account_map`.

- **Вклад: загружайте самую свежую накопительную выписку** (например, с 01.04 по сегодня). В ней есть все прежние строки; уже записанное бот узнаёт («Дубли»), создаёт только новое.
- Промежуточная накопительная выписка может печатать неверный «остаток на конец». Бот блокирует её (`parse_error` → `balance_mismatch`). Это ожидаемо, не сбой: возьмите более свежую выписку.
- Если в периоде есть процентная строка первого дня (проценты прошлого месяца банк уже включил в «остаток на начало»), бот покажет `balance_interest_unreconciled` и `balance_not_verified`. Решение за вами: принять риск после проверки строк.
- Сдвиг остатков между соседними выписками даёт `balance_discontinuity` ([Блокировки](faq/blocks.md)).
- Накопительная и недельная выписки с общим периодом: достаточно накопительной. Если загрузить обе одним пакетом, одинаковые строки не задвоятся, но ошибка в любом файле блокирует весь пакет.
- Операции «в ожидании» (hold) исключаются (`rows_pending_hold_excluded`). Они придут проведёнными в следующей выписке.
- Пополнение с описанием «Снятие со вклада» считается поступлением с вклада, указанного в `[forte] savings_account_suffix`.

## Kaspi {#kaspi}

- Поддерживается только **Kaspi Gold**, PDF на русском, счёт в тенге (KZT). Другая валюта даёт `currency_unsupported`, другой формат — ошибку разбора.
- «Доступно» в шапке Kaspi включает заблокированные суммы и не является остатком, поэтому каждый импорт Kaspi требует `принять риск` (`balance_not_verified`).
- `Покупка` со знаком `+` и фразой про курсовую разницу — корректировка курса. Если в той же выписке есть ровно одна подходящая покупка на том же счёте за 0–7 дней до неё, корректировка не больше 10 % суммы и магазин совпадает (если указан), бот уменьшает сумму покупки и отдельную операцию не создаёт (пометка «сумма покупки уменьшена на курсовую разницу»). Иначе строка уходит во «вручную».
- `Покупка +` без такой фразы автоматически не считается возвратом: `row_unknown_type` → «вручную».
- Категории сводки («Разное», «Переводы на свои счета» и т. п.) сверяются только общей суммой. Расхождение даёт `summary_total_mismatch` или `turnover_mismatch`.

## Halyk {#halyk}

Мультивалютная карта: один файл содержит несколько счетов.

- На каждую пару «IBAN + валюта» — своя запись `account_map`, иначе `unmapped_account`.
- Если в строке не указан счёт списания, но итоги по счетам сходятся только при одном распределении, бот выбирает его сам. В preview будет `Счёт списания определён по итогам выписки ... для N операций`, и перед подтверждением нужно нажать `Счета списания проверил — продолжить`. Если распределений несколько — `row_account_ambiguous`, импорт заблокирован.
